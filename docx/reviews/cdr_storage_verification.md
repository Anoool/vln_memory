# CDR 存储策略验收

日期为 2026-11-05。实现分支为 codex/preparation-optional-cdr，代码基线为 a13b5d0，方案检查点为 20154a1。

当前 BagBuilder 输出 v7，默认 save_raw_cdr=false，messages 及嵌套 source 的 raw_path 为 null。true 模式明确保存 CDR。两个读取入口均支持 v5/v6/v7，并按声明检查原始文件。

构造录包回归覆盖默认配置、严格布尔类型、true/false 逐条提取结果与媒体字节等价、实际输出容量、原始输入长度上限、旧格式、缺失 CDR、策略矛盾、转换重试、既有目标、路径重叠和失败时禁止发布。

ROS CTest 18/18、无 ROS 核心 CTest 10/10 通过。ROS 安装消费者验证 BagBuilder、读取器和转换接口，无 ROS 安装消费者回读精简后的真实短包并复跑既有投影数值对照。

真实输入为 build/depth-png-ab-20261104/short.db3。分别执行米制 NPY 与源 PNG16 的无 CDR 重导出，并转换对应历史 v6 数据。每种结果均以源 SQLite 独立检查 134 条消息的长度和 SHA-256、38 条标定、36 帧原始 header/模型/像素及 10 对 RGB-D，报告差异为零。

新导出和转换结果均通过新旧读取入口对照及既有三个投影点的独立数值参考。prepared_pairs=0，10 对数据继续保留注册未核实的 pending 原因。该验证针对软件提取与数值一致性。

| 深度存储及操作 | 原目录字节数 | 新目录字节数 | 净减少字节数 |
| --- | --- | --- | --- |
| 米制 NPY 重导出 | 78,250,153 | 74,679,706 | 3,570,447 |
| 米制 NPY 转换 | 78,250,153 | 74,679,885 | 3,570,268 |

PNG16 重导出在本固定短包上净减少约 26.3%。转换结果包含额外的来源字段，因此净体积与重导出略有差别。原数据和原始 SQLite 保留，验收输出、报告及日志位于被 Git 忽略的 build/cdr-real-check-*。

audit_camera_dataset.py 继续面向该 D435i 有限 D8 模型数据，支持 v4–v7。省略 CDR 时使用只读源 SQLite 查找相同话题、记录时间、长度及摘要的消息，并独立核对标定和媒体。它的设备假设与模型支持边界保持在脚本检查中。

部署时应重新编译依赖 PreparedPair 的 C++ 消费者，可选 raw evidence 路径由调用方检查。输入数据集在转换和索引读取期间应保持稳定，大小及修改时间检查的保证范围见模块说明。
